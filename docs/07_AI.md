# AI Strategy

## Core Philosophy

> **AI never decides. AI suggests. AI always explains confidence. AI always asks confirmation before changing business data.**

PayMuster's AI is an intelligent assistant — not an autonomous agent. It operates under the strict constraint that no AI output can modify, create, or delete any business record without explicit human confirmation. Every suggestion includes a confidence score, and the user always has the final say.

This is not a design choice — it is a trust requirement. Construction business owners will not adopt software that makes financial decisions on their behalf. The AI must earn trust by being transparently helpful, never opaque or presumptuous.

---

## What AI Learns

The AI continuously learns from the organization's operational patterns to make increasingly relevant suggestions over time.

| Learning Domain | What It Observes | How It Uses It |
|---|---|---|
| **Expense Categories** | Historical expense descriptions and their assigned categories | Auto-suggests category when a new expense is entered |
| **Notes & Descriptions** | Common phrases and naming patterns used by the org | Auto-complete suggestions for free-text fields |
| **Worker Patterns** | Which workers are frequently assigned to which sites, typical hours, common overtime patterns | Suggests optimal site assignments, flags unusual absences |
| **Site Patterns** | Typical workforce size per site, seasonal fluctuations, material consumption rates | Forecasts labor and material needs for a site |
| **Expense Patterns** | Recurring expenses (fuel every Monday, rental payments on the 1st) | Reminds users of expected recurring expenses |
| **Payment Styles** | Preferred payment modes per worker, common payment schedules | Pre-fills payment mode, suggests batch payment groupings |

### Learning Rules
- AI learning is **organization-scoped**. One org's data never influences another org's suggestions.
- AI models are **retrained or updated** only on confirmed, human-approved data — never on drafts, rejections, or unverified records.
- Users can **dismiss or correct** any AI suggestion, and the correction is fed back into the learning loop.

## AI Features

### 1. Smart Expense Categorization
- **Trigger**: User types an expense description (e.g., "Diesel for generator at Site Alpha").
- **Action**: AI suggests "Fuel" as the category with 92% confidence.
- **UI**: Category field is pre-filled with the suggestion. A small badge shows "AI Suggested · 92%". The user can accept, change, or dismiss.
- **Learning**: If the user changes the category, the correction is stored and improves future suggestions.

### 2. Attendance Anomaly Detection
- **Trigger**: After attendance is marked for the day, AI runs a background check.
- **Examples of Anomalies**:
  - "Worker Rajesh has been absent every Monday for 4 consecutive weeks."
  - "Site Alpha had 12 workers yesterday but only 3 today — 75% drop."
  - "Worker Sunil was marked present at Site Alpha and Site Beta on the same day."
- **Action**: Anomalies appear as non-blocking notifications in the Supervisor/Admin dashboard. They are informational, not blocking.
- **UI**: A card in the Dashboard with an amber warning icon. Tapping it shows the details and a "Dismiss" button.

### 3. Payroll Estimation
- **Trigger**: User asks "What will next month's payroll be?" or navigates to the Payroll module before a pay cycle is created.
- **Action**: AI calculates an estimate based on:
  - Currently active workers and their configured rates.
  - Average attendance patterns from the last 3 months.
  - Pending advances that will be deducted.
- **Output**: "Estimated payroll for August 2026: ₹4,82,000 (±₹35,000 based on attendance variance)."
- **UI**: Displayed as a clearly labeled estimate card. Never presented as a confirmed amount.

### 4. Natural Language Report Queries
- **Trigger**: User types a question in the AI Assistant panel.
- **Examples**:
  - "How much did we spend on fuel last month?"
  - "Show me all workers who worked overtime in July."
  - "What is the total material cost for Site Alpha?"
- **Action**: AI translates the natural language query into a structured report query, executes it, and presents the results in a table or summary card.
- **Guardrails**: AI can only execute read-only queries. It cannot modify data via natural language commands. If the user asks "Delete worker Rajesh," the AI responds: "I can't make changes to records. Please use the Staff module to manage workers."

### 5. Smart Suggestions (Contextual)
- **Staff Module**: When creating a new worker, AI suggests common rate configurations based on similar workers in the org.
- **Site Assignment**: When a new site is created, AI suggests workers who are currently unassigned and have relevant skill history.
- **Material Reorder**: When stock drops below the reorder level, AI suggests the vendor and typical order quantity based on past inward transactions.

### 6. Photo-Based Material Identification
- **Trigger**: User uploads a photo of a material delivery/invoice.
- **Action**: AI identifies the material type and quantity, suggesting the category.
- **Guardrails**: Extraction is sent to the backend Vision API. No on-device processing to save app size. User must manually confirm the extracted data before saving.

## Confidence Scoring

Every AI suggestion includes a confidence score:

| Confidence | Display | Behavior |
|---|---|---|
| **≥ 90%** | Green badge: "High Confidence" | Suggestion is pre-filled in the input field. User can accept with one tap. |
| **70–89%** | Amber badge: "Suggested" | Suggestion is shown as an option but NOT pre-filled. User must actively select it. |
| **< 70%** | Gray badge: "Low Confidence" | Suggestion is shown as a footnote. Not prominent. |
| **No data** | No badge | AI does not show a suggestion. Falls back to manual input. |

## AI Architecture

### On-Device (Flutter)
- Lightweight pattern matching for expense auto-categorization (runs offline).
- Cached lookup tables for common suggestions (synced from server).
- No LLM runs on-device.

### Server-Side
- **Expense Categorization**: Fine-tuned text classification model or LLM with few-shot prompting per org.
- **Anomaly Detection**: Rule-based engine augmented with statistical outlier detection (no deep learning — construction data is too sparse for complex models).
- **Natural Language Queries**: LLM (e.g., GPT-4o or self-hosted Llama 3) with structured output parsing. The LLM generates a structured query spec, which is validated and executed by the report engine — the LLM never runs raw SQL.
- **Payroll Estimation**: Deterministic calculation engine (not ML) using attendance averages and configured rates.
- **Vision/Material ID**: Proxy to a cloud Vision model (e.g., GPT-4o-mini) to extract structured data from images.

### Privacy & Data Handling
- **No PII sent to third-party LLMs**: Worker names, phone numbers, bank details, and Aadhaar numbers are NEVER included in LLM prompts. Only anonymized descriptions, categories, and aggregate patterns are used.
- **Org-Scoped Models**: Each organization's learning data is isolated. No cross-tenant data leakage.
- **User Control**: Organization admins can disable AI suggestions entirely from Settings.
