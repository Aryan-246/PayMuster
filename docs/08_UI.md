# UI/UX Architecture & Design System

## Overview

PayMuster is a dual-platform application:
- **Flutter Mobile App**: The primary interface for field operations — attendance marking, photo capture, GPS tracking. Optimized for construction workers and supervisors.
- **React Web Dashboard**: The administrative interface for payroll processing, reporting, settings, and data-intensive workflows.

Both platforms share the same design language, color system, typography, and component philosophy — but each is optimized for its medium.

---

## Design Philosophy

| Principle | Rule |
|---|---|
| **Industrial** | The design must feel engineered, precise, and sturdy — like well-built machinery. No playful colors or whimsical illustrations. |
| **Premium** | The app must feel expensive. Subtle shadows, smooth animations, and immaculate spacing signal quality. |
| **Minimal** | Every element on screen must justify its existence. If it doesn't help the user complete a task, remove it. |
| **Dark** | Dark backgrounds reduce eye strain in bright outdoor environments and convey professionalism. |
| **High Contrast** | Text and interactive elements must be immediately distinguishable against dark backgrounds. |
| **Glove-Friendly** | Touch targets must be ≥ 48dp. Buttons must have generous padding. Swipe gestures must be forgiving. Workers wearing PPE gloves must be able to operate the app. |

### Anti-Patterns (Do NOT Do)
- Do NOT use light/white backgrounds as default.
- Do NOT use small text below 14sp on mobile.
- Do NOT require precise tapping (no tiny checkboxes, no small dropdown triggers).
- Do NOT use excessive animations that slow down task completion.
- Do NOT copy any existing agri-tech, HR, or attendance app's visual design.

## Color System

| Token | Hex | Usage |
|---|---|---|
| `--bg-primary` | `#0B1114` | App background, page background |
| `--bg-secondary` | `#121A1F` | Sidebar, secondary panels, input backgrounds |
| `--bg-card` | `#182126` | Card surfaces, table rows, modal backgrounds |
| `--accent-yellow` | `#F4B400` | Primary action buttons, highlights, active states |
| `--accent-green` | `#00C853` | Success states, "Present" status, payments received |
| `--accent-red` | `#FF5252` | Error states, "Absent" status, destructive actions |
| `--accent-blue` | `#42A5F5` | Links, informational badges, secondary actions |
| `--text-primary` | `#FFFFFF` | Headings, primary labels, button text |
| `--text-secondary` | `#B0BEC5` | Body text, descriptions, timestamps |
| `--border` | `rgba(255,255,255,0.08)` | Card borders, dividers, input outlines |

### Semantic Color Rules
- **Present** = Green (`#00C853`)
- **Absent** = Red (`#FF5252`)
- **Half Day / Pending** = Yellow (`#F4B400`)
- **Leave / Holiday** = Blue (`#42A5F5`)
- **Approved** = Green
- **Rejected** = Red
- **Draft / Pending Approval** = Yellow

## Component System (MusterUI)

### Cards
- Background: `--bg-card` (`#182126`)
- Border: `1px solid var(--border)`
- Border Radius: `12px`
- Padding: `16px` (mobile), `20px` (web)
- Shadow: `0 2px 8px rgba(0,0,0,0.3)` — subtle, never heavy

### Buttons
- **Primary**: Background `--accent-yellow`, text `#0B1114` (dark on yellow for contrast). Height: 48px minimum.
- **Secondary**: Background `transparent`, border `1px solid var(--border)`, text `--text-primary`. Height: 44px minimum.
- **Destructive**: Background `--accent-red`, text `#FFFFFF`. Always requires confirmation dialog.
- **Border Radius**: `8px` for all buttons.
- **Touch Target**: Minimum 48dp × 48dp on mobile (even if the visual button appears smaller, the tappable area must meet this).

### Inputs
- Background: `--bg-secondary`
- Border: `1px solid var(--border)` — focus state: `1px solid var(--accent-yellow)`
- Height: 48px minimum on mobile, 40px on web
- Padding: `12px 16px`
- Border Radius: `8px`
- Placeholder text: `--text-secondary`

### Tables (Web Dashboard)
- Header row: `--bg-secondary` with `--text-secondary` labels in Medium (500) weight.
- Body rows: `--bg-card` with subtle hover effect (`rgba(255,255,255,0.04)`).
- Sticky header on scroll.
- No zebra striping needed on dark themes — the card boundary provides sufficient contrast.
- Row height: 48px minimum.

### Modals & Dialogs
- Overlay: `rgba(0,0,0,0.6)`
- Modal background: `--bg-card`
- Border Radius: `16px`
- Confirmation dialogs for destructive or financial actions must have a clear "Cancel" button and a red "Confirm" button.

### Navigation (Sidebar — Web)
- Background: `--bg-secondary`
- Width: 240px (expanded), 64px (collapsed)
- Active item: `--bg-card` background with `--accent-yellow` left border accent (3px)
- Icons: 20px, `--text-secondary` inactive, `--text-primary` active

### Navigation (Bottom Tab — Mobile)
- Background: `--bg-secondary`
- 5 primary tabs: Dashboard, Staff, Attendance, Payroll, More (overflow menu)
- Active tab: `--accent-yellow` icon + label
- Inactive tab: `--text-secondary`

## State Handling

Every interactive view must handle 4 states explicitly:

| State | Visual Treatment |
|---|---|
| **Loading** | Skeleton placeholders matching the expected layout. Never a spinner blocking the full screen. |
| **Empty** | Illustration or icon + message + primary action CTA (e.g., "No workers added yet. Add your first worker.") |
| **Error** | Red accent card with error message + "Retry" button. Never a raw error code. |
| **Populated** | The standard data view with full interactivity. |

---

## Animation Guidelines

- **Transitions**: 200ms ease-out for page transitions, modal opens/closes.
- **Micro-interactions**: 150ms for button press feedback, toggle switches, checkbox fills.
- **Loading**: Shimmer effect on skeleton placeholders (subtle left-to-right light sweep).
- **Never**: No bounce effects, no parallax scrolling, no decorative particle effects.

| Breakpoint | Width | Layout |
|---|---|---|
| **Mobile** | < 768px | Single column, bottom navigation |
| **Tablet** | 768px – 1024px | Collapsible sidebar, fluid grid |
| **Desktop** | > 1024px | Full sidebar, multi-column layouts, data tables |

---

## Accessibility Requirements

- **Contrast Ratio**: All text meets WCAG AA minimum (4.5:1 for body text, 3:1 for large text).
- **Focus Indicators**: Visible focus ring (`2px solid var(--accent-yellow)`) on all interactive elements when navigating via keyboard.
- **Screen Readers**: All icons have `aria-label`. All form inputs have associated `<label>` elements.
- **Reduced Motion**: Respect `prefers-reduced-motion` media query — disable non-essential animations.
